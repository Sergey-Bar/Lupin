# Lupin 5.0.0 — the public release (2026-11-18)

Ship 5.0.0 as the self-hosted zip and OCI images (`release.yml`) and as `@lupin/cli` and
`@lupin/playwright-reporter` on npm (`npm-publish.yml`). A QA engineer or SDET installs it,
connects a repository, wires CI, and gets health, flakiness, AI-era signals and a release
verdict, each proven by a test. No date: the release ships when `pnpm release:readiness` is
green. Work happens on `release/5.0.0-readiness`, one commit per task.

## The release, as data

`docs/quality/release-journeys.json` lists seven journeys (onboarding, CI ingestion, release
verdict, AI signals, notifications, triage, MCP) and seven connectors (GitHub, Jira, Slack,
Teams, Telegram, WhatsApp, Signal). `scripts/release-readiness.mjs` fails on a missing spec, a
journey resting on a capability that is not `real`, a connector below `fake-verified`, and an
open or debt Blocker or Critical. On 2026-11-18 it reported 20 gaps: six journey specs not yet
written and every connector at `none`. Every journey already rests only on `real` capabilities.

## Decisions

| Decision                           | Choice and reason                                                                                                                                                                                                                                                                                                         |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Version                            | 5.0.0. `npm-publish.yml` publishes at the tag's version, so both tools move from 1.0.0 to 5.0.0 on purpose and stay in lockstep with the product. The release notes tell CI users to pin `@lupin/cli@^5`.                                                                                                                 |
| Connector proof                    | `fake-verified` is the release bar: an E2E spec drives each adapter against a fake built from the platform's public API docs, with the source URL and read date beside each schema. `live-verified` is opt-in through a `connectors-live` workflow that records `not_configured` without secrets, and is left to contributors. |
| AI                                 | Deterministic failure clustering for everyone; an LLM summary only when a provider is configured, labelled as AI-generated and never an input to the verdict. Mock AI capabilities stay off every screen.                                                                                                                  |
| Telemetry                          | None. Time to first verdict and upload activity are shown to the operator, locally.                                                                                                                                                                                                                                       |
| Dogfooding                         | Required: a nightly job boots the stack in the job and grades this repository. Optional: the same upload to the reference install, `not_configured` when that host is absent.                                                                                                                                             |

## Mock surfaces on screen

The capability register's mock rows are `auth.service-credentials`, `orchestration.inventory`,
`runner.control-plane`, `runner.oci`, `tool.playwright`, `automation.chat`, `automation.agents`,
`ai.catalog` and `migration.tool`. Read against `apps/web/src` on 2026-11-18, no screen calls the
chat-completion route or an AI catalog, and the copilot answers from the rule engine and cites
what it read. The one overstatement was copy: the AI provider page and the setup step said a
provider "powers chat". Both now name only test proposals and evals, and
`SettingsForm.test.tsx` and `SetupWizard.test.tsx` fail if "chat" comes back.

## Release blockers found outside the ledger

- **`main` is red.** The Rendering budget job failed on `unified-ci.yml` run 43395721046
  (2026-11-13): LCP 488–548 ms against a 460 ms ceiling on `/dashboard` and
  `/dashboard/quarantine`. A re-recording exists on `perf/lazy-pages` (commit `3726c48b`, ceilings
  580–1020 ms, recorded on the owner's workstation rather than the reference install). It has to
  land on `main`, or the regression has to be fixed, before the candidate is tagged. It needs a
  ledger row when it lands.

## Breaking changes since 4.1.0

Six commits are on `main` since `v4.1.0`, all dependency bumps; none changes behaviour. The
list grows with each task below, and is the source of the upgrade guide.

- Both npm packages jump from 1.0.0 to 5.0.0 (version only).
